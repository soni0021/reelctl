# Changelog

Notable changes to `reelctl`. Add an entry under Unreleased in the same commit as the change. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- `reelctl serve [--workspace <dir>]` runs the studio service: JSON-RPC 2.0 on a Unix socket (0600, the same user only, no network port) in `<dir>/.reelstudio/`, a job queue that runs each catalogue command as a child `reelctl` with `--progress json`, a content-addressed store and a SQLite catalogue, a checkpoint per finished job with revert and branch, a cache of identical jobs, events, cancel, garbage collection, `doctor.check`, and a two-step paid `understand` call that needs the plan's bound approved. See [docs/cli.md](docs/cli.md#reelctl-serve).
- `--progress json` on every command writes machine-readable progress to stderr: stages, progress with done and total, warnings, the result (the stdout line's fields) and errors with their exit code. stdout is unchanged. SIGTERM, SIGINT or SIGHUP now stops a run cleanly: its child processes (ffmpeg, the whisper worker, manimgx, Smelter) get SIGTERM, no further output file is written, temporary files are removed, `make-reels` records `"status": "cancelled"`, and it exits 130. A second signal ends the run at once. See [docs/cli.md](docs/cli.md#progress-and-cancel-all-commands).
- `reelctl make-reels --input <long.mp4> --outlier <dna>... --target-url <url> --out-dir <dir>` makes finished vertical reels from one long video:
  - It decompiles the video with whisper, plans the cost of `understand`, and asks before the paid call (`--yes` to skip asking; exit 4 without a yes or over `--max-cost-usd`). It never calls the model again for a folder that already has `understanding.json`.
  - For each clip it runs from-clip, cut-silence, auto-punch-in, the 9:16 presenter crop (centred, and said so, without RVM weights), the appended card, captions, render and `diff`, each step as its own `reelctl` process with only the environment it needs.
  - Choose clips with `--reels`, `--clips` and `--pick`, and style the captions with the same flags as `overlay captions`.
  - It writes `make_reels.json`.
  - See [docs/cli.md](docs/cli.md#reelctl-make-reels).
- `reelctl timeline from-clip` makes a project trimmed to one clip pick of `understanding.json` (`--clip N`; a flagged clip needs `--allow-flagged`), `reelctl transform auto-punch-in` adds punch-ins wherever the picture would stay still longer than `diff`'s 2.5 s limit, at the outliers' measured zoom scale, and `reelctl funnel attach-bridge --append` adds the card after the last frame without cutting. `reelctl overlay captions` burns word captions from whisper's timings, with presets (`bold`, `clean`, `boxed`, `karaoke`, `minimal`), a JSON style file and flags for font, size, colours, a highlight on the spoken word, outline, shadow, box, position, margin, words per group, wrapping and case; `render` draws them itself with your system font (Homebrew's ffmpeg has no `drawtext`), on their exact frames. `reelctl transform reframe --follow presenter|centre` crops to 9:16 (or `--aspect`): `presenter` finds the speaker with RobustVideoMatting (your weights and ONNX Runtime, as for `compositor isolate-presenter`) and moves the window smoothly after them, jumping at cuts; `render` crops each piece along the planned path. These are the first steps of `make-reels` ([spec](docs/specs/make-reels.md)).
- `reelctl compositor isolate-presenter --input --background <#rrggbb|image|video> --weights <rvm.onnx> --out` cuts a presenter out of a video with RobustVideoMatting and writes them over a solid colour, an image or a looping video (scaled to cover, never stretched). `--mode matte` writes the alpha as a grey video and `--mode rgba` writes the presenter with alpha as ProRes 4444. The model is an ONNX file you supply (`--weights` or `REELCTL_RVM_WEIGHTS`; both `fp32` and `fp16` files work) and ONNX Runtime comes from an absolute `ORT_DYLIB_PATH`; neither is bundled. Setup problems (missing weights or library, a bad background, HDR input) exit 2 before the first frame; the output appears only when the run completes. On an Apple M3 CPU the real model runs at about 80 to 180 milliseconds per 720p frame under load, not in real time. See [docs/cli.md](docs/cli.md), [docs/specs/rvm-presenter.md](docs/specs/rvm-presenter.md) and [ADR-021](docs/decisions/ADR-021-matte-presenters-with-rvm-through-a-second-onnx-session.md).
- `reelctl dataset build --dna <dir|files> [--understanding <runs>] --out <dir>` writes `train.jsonl`, `val.jsonl` and `manifest.json`: instruction-tuning records (`clip_picks` from `understanding.json` runs, `edit_events` and `pacing` from `edit_dna.json`) whose targets are measured facts or rule-checked segment IDs, never the teacher model's prose or labels. The split is by reel (from the reel id and a salt, so adding reels never moves one), output is byte-identical whatever the input order, unknown schema versions are refused, and records that cannot be built are skipped with a reason in the manifest. `reelctl eval --truth <understanding.json | dataset> --answers <file>` scores a model's answers (segment-ID agreement, clip-rule pass rate, cut and event timing error, pacing error) and prints the same report fields for every model, so a base model and a later fine-tune can be compared. Both are offline; nothing calls a model. Only `clip_picks` is trainable (the filmstrip PNGs are cut-anchored and give the answer away, so they are not attached), and training is not built. See [docs/finetune.md](docs/finetune.md), [docs/cli.md](docs/cli.md) and [ADR-024](docs/decisions/ADR-024-build-the-p3-dataset-and-eval-without-training.md).
- `reelctl overlay add-chart` and `overlay remove`: draw a bar, line or number-callout chart with `manimgx` (a separately installed worker: `--manimgx`, `MANIMGX_BIN`, or `PATH`; fail closed, no shell, time limit, output checked) and lay it over the video for a span, as a marked second `Video` track in the project that `render` composites with `colorkey` and `overlay`, exact to the frame. manimgx writes only x264 MP4, so the chart is drawn on `#ff00ff` and keyed. Chart text is data in a fixed scene file, never code or a command-line argument. The same spec twice is one overlay and the same project bytes. `cut-silence`, `punch-in` and `attach-bridge` refuse a project that has overlays (add them last). The real manimgx has not been run: it is tested against a fake, and the by-hand recipe is in [docs/timeline.md](docs/timeline.md#checking-an-overlay-with-the-real-manimgx). See [ADR-022](docs/decisions/ADR-022-draw-chart-overlays-with-a-separately-installed-manimgx-and-key-them-over-the-video.md) and [docs/cli.md](docs/cli.md).
- `reelctl render --backend ffmpeg|smelter` (default `ffmpeg`, unchanged) and `--smelter <path>` / `SMELTER_BIN`: an optional second render backend that drives a separately installed [Smelter](https://github.com/software-mansion/smelter) (v0.6.0 tested, offline mode) over its HTTP API, one server per render on a random port, and renders the same OpenTimelineIO project: cuts, the punch-in zoom sampled on every ramp frame, the bridge card, the mixer. Without a Smelter it exits 1 and says how to point at one; media Smelter cannot read exits 2 with the `ffmpeg` fix (HEVC; or PCM audio, which Smelter drops without a word, when the project plays that sound). Limits, all printed as `render:` notes and measured in [docs/status.md](docs/status.md#smelter-backend-2026-10-29): a cut, a zoom step or the card can land one or two frames early in about a third of runs under load (Smelter applies a scheduled update to frames it has queued; the sound's cuts use the same events and were not measured), the audio dip at a join is not applied, an untagged source differs in colour, and a 41-piece, 45 s, 1080x1920 project was several times slower than ffmpeg (numbers and machine load in status). The frame count is exact: Smelter is asked for four frames too many and the file is trimmed and counted. No new Cargo dependency; Smelter is never downloaded or vendored and its licence is custom (offline use is permissive, real-time use is limited). See [ADR-023](docs/decisions/ADR-023-drive-smelter-as-a-separate-process-over-its-http-api.md), [docs/specs/smelter-backend.md](docs/specs/smelter-backend.md) and `fixtures/smelter_agreement.sh`.
- `--cut-detector transnet` now runs TransNetV2 through `ort`. Give it the ONNX weights (`--transnet-weights` or `REELCTL_TRANSNET_WEIGHTS`) and an ONNX Runtime library (`ORT_DYLIB_PATH`); neither is bundled. It finds dissolves and fades the scene score misses (on the `dissolve12` fixture) at about 7 ms per frame, so `--cut-detector auto` uses it only when a weights path is given and otherwise, or if anything is missing, falls back to the scene score and says why in `cut_detector_note`. A new `dissolve12` fixture plants a dissolve and a fade. A clip of over 200,000 frames is refused by `transnet` (it falls back under `auto`) and `ORT_DYLIB_PATH` must be an absolute path; a probability outside 0 to 1 or not a number is an error, and a run over 9,000 frames says how long it took in the note. See [docs/cli.md](docs/cli.md) and [ADR-018](docs/decisions/ADR-018-run-transnetv2-through-a-dynamically-loaded-onnx-runtime.md).
- `reelctl look --draft --outlier --out` writes a `.cube` 3D LUT that matches a draft's colour to an outlier's by per-channel histogram matching on sampled frames (sizes 17, 33, 65). It transfers a grade between clips of the same content and gives poor results between very different content. See [docs/cli.md](docs/cli.md).
- `reelctl timeline init|cut-silence`, `transform punch-in`, `funnel attach-bridge`, `render` and `qa inspect-boundaries`: deterministic, idempotent edits over an OpenTimelineIO project (our own reader and writer for the subset, loads in the reference library 0.18.1) and an `ffmpeg` render. `cut-silence` removes pauses of 180 ms or more and filler words with a 30 ms audio dip at each join; `punch-in` adds a zoom; `attach-bridge` cuts at 72% and appends a URL card. Media must be a local regular file (no URLs or ffmpeg protocols), words inside a silence gap are never cut, and `--size` is capped at 8192 a side. See [docs/timeline.md](docs/timeline.md).
- `watchtower`, a Go module (`watchtower/`, run `watchtower run --data <dir> --out <dir>`) that computes each creator's outlier multiplier and 7-day growth velocity from recorded niche data, decompiles breakout Reels with `reelctl decompile`, compares the last five breakouts with baseline posts on measured fields (shot length, cuts and pauses per minute, silent share, words per minute, loudness, visual events), and writes `digest.json` and `digest.md`. It reads files only: a live Virlo client is not built. It validates `media_path` (inside the data directory, no `..`, no absolute path) and post ids (unique, safe characters), labels burst rates as voiced bursts, and has `--reelctl-timeout` (default 5 minutes). See [docs/watchtower.md](docs/watchtower.md).
- `edit_dna.json` (schema version 4): `zoom_curves` now holds a fitted easing curve, `cubic-bezier(1/3, y1, 2/3, y2)`, for each measured punch-in and zoom-out, with its samples and fit error (`bezier` is `null` for a move too short to fit). Version 1 to 3 files still read with `status: unimplemented`. See [docs/edit-dna.md](docs/edit-dna.md).
- `edit_dna.json` (schema version 3) gains `visual_events`: punch-ins and zoom-outs with their measured scale and centre, and overlay changes (a caption box, chart, panel or B-roll card appearing or going) with the share of the frame they cover, found from the luma grids the decoder already builds, with no cut. `reelctl diff` no longer calls a stretch a static window when an event splits it. Version 1 and 2 files still parse. See [docs/specs/visual-motion.md](docs/specs/visual-motion.md).
- `reelctl understand` picks Reel-sized clips from a long video and labels its cuts, using a hosted vision-language model through OpenRouter (default `qwen/qwen3.5-9b`, under 1¢ per 28-minute lecture: $0.0082 measured, bound $0.0277). The model sees sampled frames and numbered transcript segments and answers by segment ID, so every quote is whisper's text and every time is measured; code applies the clip rules (open on the hook, end on the cliffhanger, 30–60 s once pauses are cut) and flags what it cannot meet. `--dry-run` plans and prices without a key. Exit code 3 without `OPENROUTER_API_KEY`, 4 when the cost upper bound is over `--max-cost-usd`. Every request denies data collection. See [docs/understanding.md](docs/understanding.md). The prompt states the clip length in segments for the video at hand, which took Qwen3.5-9B from no clip within 30–60 s to four of five on one 28-minute lecture (a single run each, a direction and not a rate) ([ADR-016](docs/decisions/ADR-016-state-the-clip-length-in-segments-not-seconds.md)).
- `reelctl diff` takes `--outlier` one to three times and prints a `comparison` next to `flags`: per-reel metrics (shots, pauses per minute, silent share, speaking rate, loudness), cut counts in 5 s windows, and two relative findings, `rhythm_gap` (the draft has no cut where most outliers do) and `pause_density`. `--format text` prints a readable table. `flags` is unchanged for one outlier; with several, the missing-payoff flag needs a cue in more than half of them.
- `reelctl decompile` writes `edit_dna.json` (cuts, silence gaps, loudness, per-shot color, the 9-second payoff cue, and the measured `signal_ms`) and one `timeline_view` PNG per cut.
- `reelctl diff` flags dead air over 180 ms, more than 2.5 s without a cut, and a missing payoff cue compared with an outlier's `edit_dna.json`.
- A JSON Schema for `edit_dna.json`.
- Synthetic test clips (`fixtures/generate.sh`), including `speech12` and `tonespeech` with synthesized speech on macOS, and end-to-end tests.
- whisper runs in a child process. A whisper.cpp abort, which 1.8.3 can hit on short windows with DTW on, no longer ends `reelctl`: the pass is retried without DTW and `asr_note` says so. `REELCTL_PROFILE=1` also prints `asr_first_ms` and `asr_second_ms`.
- With a whisper model, stretches of sound that whisper.cpp left without words are transcribed a second time, and `asr_note` lists them. On a 60 s iPhone clip this brought the word count from 125 to 183.
- `--decoder <auto|software>` on `decompile` and `diff`. With `auto`, HEVC video decodes on the Apple media engine on macOS (the 87 s iPhone recording: 4.0–5.3 s against 8.5 s, with a tenth of the CPU time), and the output is the same as a software decode, including for full-range 8-bit video and for streams that change size. If the media engine fails, the file is decoded again in software and `decode_note` says why.
- `reelctl decompile` reads 10-bit 4:2:0 video (`yuv420p10le`), so iPhone HEVC Main 10 recordings no longer need converting first. `decode_note` says when the video was 10-bit and when it was HDR (HLG or PQ), whose colors are not tone-mapped. 8-bit input gives the same output as before.
- Project docs: README, status, CLI and `edit_dna.json` references, and decision records.
- `--whisper-model` now transcribes with whisper.cpp: `words` are real words timed with DTW, `words_per_minute` is a real speaking rate, and `asr_backend` is `"whisper_cpp"`. English-only and multilingual models work, including the Hinglish Apex fine-tune.

### Changed

- A very quiet recording is no longer one giant silence gap. When the loudest 1% of a recording's 10 ms windows are quieter than −28 dB, the silence threshold goes below −40 dB (to 12 dB under that loud part, never below −70), so `diff` stops reporting the whole file as dead air. On a 15 s Instagram download with almost no audio, one 15 s gap became three short ones. A track that is digital silence, or has under 1% sound, now reports a threshold of −70 instead of −40 with the same gaps. Without a whisper model, a quiet recording also gets burst "words" and a words-per-minute figure where it used to get none or one, because the bursts use the same threshold. Recordings of normal loudness are unchanged.
- A video whose frame size changes part-way now decodes. A smaller frame used to stop with `luma sample walked past the plane`, and a larger one was scored over only the part of the picture the size of the first frame. The scene score now compares frames of different sizes by position. Video of one size is unchanged.
- A video frame is read as full range if it is `yuvj420p` or its metadata says full range. Before, a `yuv420p` frame flagged full range (as VP9 and AV1 files can be) was read as limited, so its per-shot colors and thumbnails were off. Files in the usual limited range are unchanged.
- Software decoding now runs the loop filter on every frame. It used to skip it on non-reference frames, which saved 6% of decode time but moved HEVC scene scores by up to 0.022 against the hardware decoder. Cuts, scene scores, colors, and thumbnails of the existing test clips are unchanged; `decode_note` no longer mentions skipping the loop filter.
- Audio that is not 48 kHz is now resampled as one stream instead of one decoded frame at a time. Per-frame resampling dropped a fractional sample at each frame, so at 44.1 kHz silence gaps and word times came out early: a pause at 50 s by 16–33 ms, and about 0.5 s by 18 minutes. 48 kHz audio is untouched. The interpolation is linear with no low-pass filter, so audio above 48 kHz (88.2 or 96 kHz) can alias.
- `edit_dna.json` is now schema version 2, with `silence_threshold_db` and `noise_floor_db`. Version 1 files still load in `reelctl diff`.
- `silence_gaps` now uses a threshold set from each recording's own levels instead of a fixed −40 dBFS, and a sound shorter than 30 ms no longer splits a gap. Pauses under room noise become gaps, so `diff` now flags dead air in real recordings; on a 60 s iPhone recording, gaps of 300 ms or more went from 0 to 24. Clean recordings get the same gaps as before. Without a whisper model, burst words use the same threshold, so `words_per_minute` changes on noisy recordings.
- An unsupported pixel format's error now names the format, for example `unsupported pixel format yuv422p`.
- `reelctl --help` no longer says `--whisper-model` is ignored.
- Without `--whisper-model`, `asr_note` now says no model was given, instead of saying whisper.cpp is not linked.
- A `--whisper-model` path that is missing or not a usable whisper model now exits with code 1. It used to be ignored.
- Building now needs CMake, because the `whisper-rs` dependency compiles whisper.cpp 1.8.3 from source.
